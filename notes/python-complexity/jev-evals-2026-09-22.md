# Jev complexity evals — 2026-09-22

The integration works, but the current rubric does not reliably separate all
of the readability cases this skill cares about. In the first declared fixture
run, **6 of 9 semantic expectations passed and 3 failed**. All five requests
completed and passed response validation. Failed expectations remain in the
suite and in the recorded results.

## Run it

From the marketplace root:

```sh
# Ruff, ty, formatting, and 61 offline contract/evaluator tests.
make test-python-complexity

# Fixture behavior and static measurements; no Jev calls.
make eval-python-complexity EVAL_ARGS=--offline

# One live Jev request per case (five total), using the default provider config.
make eval-python-complexity

# Explicit provider; credentials are selected for that provider only.
make eval-python-complexity EVAL_ARGS='--provider typesafe'

# Another provider configuration, with results in a new/empty directory.
make eval-python-complexity EVAL_ARGS='--config /absolute/provider.json --output-dir /tmp/jev-run-1'
```

The runner prints its artifact directory and saves source fixtures, measured
static output, exact submitted states, per-case request/response reports, and
`summary.json`. A missing selected key skips the semantic checks and continues
static analysis. Exit `0` can therefore mean `static_only`; inspect statuses,
not only exit codes. A semantic expectation failure exits `1`, and a tool/API
failure exits `2`. These eval thresholds are **not production quality gates**.
`make test-python-complexity` never calls a provider.

## What is tested

[Fixtures](../../tests/fixtures/python-complexity-jev.json) contain four complete
implementations of the same classification contract: nested conditionals, flat
guards, redundant forwarding helpers, and a dense ternary expression. All four
match independently labeled expectations on **119 inputs each (476 checks)**.
A fifth fixture omits a necessary helper to exercise missing-context handling;
it is deliberately excluded from behavior equivalence tests.

Static-tool checks confirm the intended traps:

| Shape | Defs | Max cyclomatic | Sum cognitive |
|---|---:|---:|---:|
| Nested | 1 | 6 | 15 |
| Flat | 1 | 6 | 5 |
| Forwarding layers | 6 | 6 | 5 |
| Dense ternary | 1 | 1 | 15 |

Flattening reduces nesting cost. Redundant forwarders add functions without
removing decisions. The ternary lowers cyclomatic complexity while retaining
high cognitive complexity. Those checks passed with Ruff 0.15.16 and complexipy
7.0.1.

## Live outcomes

[Recorded results](jev-eval-results-2026-09-22.json) include all nine expectations,
raw answer distributions, provider/model metadata, rubric/state hashes, token
usage, and request identifiers. There was one request per fixture, with no
retries and no discarded responses. Vercel reported zero billed cost for these
requests; this is an observation about this run, not a pricing promise.

| Expectation | Observed | Result |
|---|---|---|
| Flat simpler than nested by at least 0.25 | 2.99 vs 2.86; gap 0.13 | **Fail** |
| Flat more readable than nested by at least 0.25 | 2.99 vs 2.94; gap 0.05 | **Fail** |
| Forwarders lower abstraction quality by at least 0.5 | 3.00 vs 0.36; gap 2.64 | Pass |
| Forwarders lower simplicity by at least 0.5 | 2.99 vs 0.58; gap 2.41 | Pass |
| Dense ternary less readable by at least 0.25 | 2.99 vs 2.97; gap 0.02 | **Fail** |
| Label forwarding cost | `indirection` | Pass |
| Label nested cost | `nesting` | Pass |
| Missing-context sufficiency probability at most 0.3 | 0.10 | Pass |
| Abstain on dominant cost without necessary context | `insufficient_context` | Pass |

The readability scores clustered near the top of the scale despite real
structural differences. Simplicity detected redundant forwarding but did not
clear the declared effect size for nesting. Do not use these scores as automatic
refactor acceptance rules. The positive findings support using abstraction and
context judgments as additional inspection signals on these examples.

These are small, synthetic regression cases, not a held-out benchmark. The
expectations were set after the earlier exploratory three-case smoke test and
before this run; the rubric and thresholds were not tuned to turn these failures
green. One request per fixture does not establish stability across repeated
calls, providers, real repositories, or model updates. No project-wide accuracy
claim follows from 6/9.

The TypeSafe native `noul` protocol was also live-tested through Vercel's
`/typesafe/v1/systemone` endpoint with the existing Vercel key. Request adaptation
and normalization succeeded. Direct TypeSafe authentication is covered by mocked
contract tests and was **not** live-tested with a TypeSafe key.

## Follow-up criteria

Before tuning this rubric, add distinct real-function and complete-path examples
with independently assigned judgments, especially meaningful abstractions that
must be retained. Keep these regression cases, use different cases to validate
any rubric change, and report unchanged as well as improved dimensions. A model
score cannot override known missing evidence or failing behavior tests.
