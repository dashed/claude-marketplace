## [1.1.0] - 2026-09-08

### Added
- The path-level census — the per-function census read one level up. New SKILL.md section "When every function scores low" built on a layering fixture triple: one behaviour written as one function (cyclomatic 20 / cognitive 47), as 26 pass-through layers with a `method` selector threaded through 10 signatures (max **3 / 3**), and as 9 functions split by meaning (4 / 7); 2 seeds × 20,000 random inputs × 15 reads = 600,000 differential comparisons, 0 mismatches. Sorted by cognitive the way the skill prescribes, the pass-through split ranks *best* — layer-golf, the third golf after comprehensions and ternaries
- Two sums from the census already run: **Σ cognitive** (Campbell v1.7 p. 10: "aggregate numbers become useful") and **decisions = Σcyclo − defs − nested defs** (McCabe 1976 p. 314: complexity sums over components and *v = π + 1*), which is invariant under extraction (19 → 20 → 9 on the triple) and to `@overload` stubs (59 − 25 = 57 − 23 on a real module)
- Three counts no census gives: callables entered per public call (static — every arm, what a reader must read; dynamic — one input, what runs; report both), argument threading (a name through three or more signatures is a pass-through variable), and selector sites by role. Verified on a real read path: 23 defs / Σcog 61 / 34 decisions against the 7 / 24 / 9 it replaced; a selector compared in 8 places across 4 functions, 8 signatures + 2 overload stubs, 3 producers; 24 branch-owned hops unpruned, 19 + 2 generated constructors after pruning untaken arms
- `scripts/` — stdlib only, run on Python 3.10.15 and 3.14.7: `path_census.py` (Σ/max/decisions/NLOC per file set or static path; de-duplicates overload stubs and nested rows; refuses to run if `ruff --show-files` misses a file), `hops.py` (static resolver with `--own`, `--exclude`, `--leaf-decorator`; prints unresolved and heuristic sites, never hides them), `hops_dyn.py` (`sys.setprofile` counter with invocation counts), `arg_threading.py` (threading table plus selector sites, overload stubs flagged)
- `references/between-function-complexity.md` (measurement: definitions, the triple, the two sums, hops static and dynamic, threading and selector sites, intermediate representations, predicting what a refactor breaks, the ruff PLR census, and the silent failures of every tool involved) and `references/layering-review.md` (judgment: structure or safety, the layer → invariant → verdict table, sibling comparison, what tests pin and the coincident-constants trap, alternatives and before/after tables, ordering the work, policy questions versus layering questions)
- ruff PLR rules that see the skill's own blind-spot fixtures in the same run as C901: `PLR0913` (the 15 parameters), `PLR0915` (the 203 statements — it counts `return` and `for` as 0, so a one-line forwarder is invisible at any threshold; `-1` is rejected), `PLR1702 --preview` (a 5-deep `with` pyramid and a 5-deep `try/finally` pyramid score complexipy **0**, PLR1702 **5**). All seven defaults verified (5 / 5 / 6 / 12 / 50 / 5 / 5), all fire on `>`, `=0` lists everything. Silent failure: selecting a preview rule without `--preview` warns on stderr, prints `All checks passed!`, exits 0; ruff 0.16 `--preview` + `concise` prints rule names instead of codes
- Measured silent failures of the tools a between-function census reaches for: `python -m trace --trackcalls` ignores `--ignore-dir` and `--ignore-module` entirely; `code2flow --target-function` drops the edge at an `@overload` stub and reports 6 nodes at exit 0 for a 35-callable path, and merges two files with the same basename into one namespace; `lizard -ENS` is a running total that never resets, `lizard -Eduplicate` reports 0.00 % for an 11-line byte-identical clone, and lizard scores a file that does not parse; `radon cc` shares complexipy's nested-class blind spot, `radon mi` scores a 6 / 15 nested function 100.00 grade A, `radon hal` gives a 5-branch function volume 0

### Changed
- "Reading the pair" Low/Low cell names the distributed monster; workflow step 5 counts what a split added (callables entered, names threaded, types introduced — and whether the decisions count fell); step 6 re-reads the path, not the function; "Never gate CI" names splitting as the third construct a gate selects for; the closing "locator" paragraph limits the per-function census to one function at a time
- Thresholds sourced first-hand: McCabe 1976 §III p. 314 is now quoted from the paper (it also prescribes "modularize subfunctions" as the response to exceeding 10, which its own §IV theorem shows does not reduce the total); Definition 1 is *v = e − n + p*, the *2p* form is the program complexity; Campbell's no-threshold statement verified across pp. 1–17 including the Appendix B specification
- cyclomatic-ruff.md: "do not aggregate" qualified — raw rows do not sum, but top-level rows minus defs minus nested defs is McCabe's own sum; new section on the PLR rules with the extended census command
- cognitive-complexipy.md: complexipy rows do sum (top-level only, nested cost folded); no output format prints a total; `@overload` stubs are rows; radon shares the nested-class trap, so only ruff and lizard are safe cross-checks
- interpreting-scores.md: "The third golf: layering" added under Metric golfing; the "failed attempt" negative result qualified (the construction exists one `def` boundary up); the blind-spot list points at the PLR rules
- Description gains the between-function triggers: a function *or call path* that is too complex, over-layered, or too indirect; every function scores low but the code is hard to follow; comparing an implementation against the path it replaces; verifying a refactor reduced complexity rather than relocating it

## [1.0.0] - 2026-08-29

### Added
- Initial addition to marketplace: measuring per-function cyclomatic and cognitive complexity in Python as refactor triage, using `ruff check --select C901` and `complexipy` with nothing installed into the project. Verified against ruff 0.12.7/0.16.3/0.16.5 and complexipy 7.0.1
- The two-metric mental model and why one number is not enough, demonstrated on a measured triple — the same five conditions and six returns written as flat guard clauses, nested five deep, and as nested ternaries, scoring cyclomatic 6/6/1 against cognitive 5/15/15. Cyclomatic cannot separate them and rates the worst version lowest
- Corrected census commands. `max-complexity=0`, not `1`: C901 fires on `>`, so a threshold of 1 silently omits every complexity-1 function — precisely where the worst blind spots live (a 203-line straight-line function scores 1). Plus `--isolated` (a project's `per-file-ignores` or `exclude` zeroes results with no warning), `--ignore-noqa` (which `--isolated` does *not* imply — one file-level `# ruff: noqa: C901` otherwise makes the census print `All checks passed!` at exit 0), `--output-format concise`, and complexipy's `--plain` (the default is a box-drawn report with emoji and width-dependent wrapping that naive parsing breaks on)
- The two non-overlapping silent failures that make a clean run a lie, and the practical argument for running both tools: ruff exits `0` with `All checks passed!` on a mistyped path (guarded with `--show-files`, verified in both directions), and complexipy never reports methods inside a nested class — such a method produces zero output and exit 0, while the identical de-nested body scores 21 and exits 1
- Reading the pair: a high/low decision table, ranking by cognitive with the gap as tie-break, and the finding that a wide gap has **two** causes with different fixes — nesting (flatten to guard clauses, 15 → 5 on identical logic) and mixed boolean density (a single flat `if` with seven alternating operators measures 2/6 with zero nesting)
- The blind-spot catalogue, all measured at 1 cyclomatic / 0 cognitive: a 203-line straight-line function, 15 parameters with 7-deep attribute chains and shared mutation, a `validate_user` that sets `is_admin = True`, and nine ternaries buried in arithmetic. Plus a five-level nested-closure callback pyramid scoring cognitive **0**
- A documented complexipy 7.0.1 scoring defect, reproduced independently twice: a ternary that is an operand of an arithmetic `BinOp` or sits inside an f-string scores 0 and suppresses outward, against the published spec. Shipped with the control fixture that isolates the ternary rather than the function
- That ruff's McCabe counts **statements, not expressions** — the single fact explaining why `and`/`or`, ternaries, and comprehension `if` clauses all cost exactly 0 — and its two-directional consequence for gaming the metric
- Sourced thresholds only: cyclomatic 10 from McCabe 1976 ("a reasonable, but not magical, upper limit", ruff's default) and cognitive 15 as complexipy's tool default established by bisection, with the explicit correction that Campbell's white paper recommends **no** numeric threshold and "SonarSource says 15" is not a research finding
- Six-step workflow ending in the non-negotiable pairing with a behavior guard, and the injunction never to gate CI on the numbers — with a measured golfing example (11/18 → 1/6, behavior verified identical over 20,000 randomized inputs) where the score fell 91% and the code got worse
- Three references: `cyclomatic-ruff.md` (full C901 surface, 12 output formats, exit codes, config interference, a 35-construct measured increment table, version differences), `cognitive-complexipy.md` (flags, output modes, measured cost table, what raises nesting depth, and four places the upstream scoring docs are wrong), and `interpreting-scores.md` (the fixture corpus, the three seed heuristics tested with one needing qualification, and a failed-attempt negative result)
