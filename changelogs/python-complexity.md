## [1.0.0] - 2026-08-29

### Added
- Initial addition to marketplace: measuring per-function cyclomatic and cognitive complexity in Python as refactor triage, using `ruff check --select C901` and `complexipy` with nothing installed into the project. Verified against ruff 0.12.7/0.16.3/0.16.5 and complexipy 7.0.1
- The two-metric mental model and why one number is not enough, demonstrated on a measured triple — the same five conditions and six returns written as flat guard clauses, nested five deep, and as nested ternaries, scoring cyclomatic 6/6/1 against cognitive 5/15/15. Cyclomatic cannot separate them and rates the worst version lowest
- Corrected census commands. `max-complexity=0`, not `1`: C901 fires on `>`, so a threshold of 1 silently omits every complexity-1 function — precisely where the worst blind spots live (a 203-line straight-line function scores 1). Plus `--isolated` (a project's `per-file-ignores` or `exclude` zeroes results with no warning), `--ignore-noqa` (which `--isolated` does *not* imply — one file-level `# ruff: noqa: C901` otherwise makes the census print `All checks passed!` at exit 0), `--output-format concise`, and complexipy's `--plain` (the default is a box-drawn report with emoji and width-dependent wrapping that naive parsing breaks on)
- The two non-overlapping silent failures that make a clean run a lie, and the practical argument for running both tools: ruff exits `0` with `All checks passed!` on a mistyped path (guarded with `--show-files`, verified in both directions), and complexipy never reports methods inside a nested class — such a method produces zero output and exit 0, while the identical de-nested body scores 21 and exits 1
- Reading the pair: a high/low decision table, ranking by cognitive with the gap as tie-break, and the finding that a wide gap has **two** causes with different fixes — nesting (flatten to guard clauses, 15 → 5 on identical logic) and mixed boolean density (a single flat `if` with seven alternating operators measures 2/6 with zero nesting)
- The blind-spot catalogue, all measured at 1 cyclomatic / 0 cognitive: a 203-line straight-line function, 15 parameters with 7-deep attribute chains and shared mutation, a `validate_user` that sets `is_admin = True`, and nine ternaries buried in arithmetic. Plus a five-level nested-closure callback pyramid scoring cognitive **0**
- A documented complexipy 7.0.1 scoring defect, reproduced independently twice: a ternary that is an operand of an arithmetic `BinOp` or sits inside an f-string scores 0 and suppresses outward, against the published spec. Shipped with the control fixture that isolates the ternary rather than the function
- That ruff's McCabe counts **statements, not expressions** — the single fact explaining why `and`/`or`, ternaries, and comprehension `if` clauses all cost exactly 0 — and its two-directional consequence for gaming the metric
- Sourced thresholds only: cyclomatic 10 from McCabe 1976 ("a reasonable, but not magical, upper limit", ruff's default) and cognitive 15 as complexipy's tool default established by bisection, with the explicit correction that Campbell's white paper recommends **no** numeric threshold and "SonarSource says 15" is not a research finding
- Six-step workflow ending in the non-negotiable pairing with a behavior guard, and the injunction never to gate CI on the numbers — with a measured golfing example (11/18 → 1/6, behavior verified identical over 20,000 randomized inputs) where the score fell 91% and the code got worse
- Three references: `cyclomatic-ruff.md` (full C901 surface, 12 output formats, exit codes, config interference, a 35-construct measured increment table, version differences), `cognitive-complexipy.md` (flags, output modes, measured cost table, what raises nesting depth, and four places the upstream scoring docs are wrong), and `interpreting-scores.md` (the fixture corpus, the three seed heuristics tested with one needing qualification, and a failed-attempt negative result)
